# project-management/

Process and tracking docs for `agent-memory-sdk`, kept separate from the
shipped package. None of this ships — the wheel build only packages
`src/agent_memory_sdk` (see `[tool.hatch.build.targets.wheel]` in
`pyproject.toml` at the repo root). This folder exists so the repo root
only shows what a user pulling the library actually needs: `README.md`,
`pyproject.toml`, `src/`, `tests/`, `scripts/`.

## What's here

- **`PROMPTS.md`** — the build-prompt sequence: Step 0 context + Steps
  1–8, ENH-1..4, ORC-1..4, PH-1..6, BENCH-1..5. Paste **Step 0** first
  into any fresh agent session on this repo, then feed it steps in order.
- **`DECISIONS.md`** — single source of truth for every decision made on
  this project, dated and appended-to, never rewritten. Read before
  starting any work here, append before finishing.
- **`ARCHITECTURE.md`** — current-state design doc (component/schema/
  sequence diagrams in Mermaid). Updated in place, not appended to.
- **`BOARD.html`** — local, self-contained Kanban board (epics + stories
  as embedded JSON). Stands in for Jira, whose MCP connection isn't wired
  up for this project. A human opens it directly in a browser. **Generated**
  — do not hand-edit it, and agents should not read/grep it for board
  state either (it's one ~1700-line file). Its source of truth is
  `board/epics/*.json` and `board/stories/*.json` (one small file per
  epic/story, so many agents can update the board in parallel without
  colliding on one file, and so checking one story's state means reading
  one small file, not the whole board); after editing those, run
  `make board` (or `python project-management/board/build.py`) to
  regenerate it — or run `make install-hooks` once per clone to have a
  pre-commit hook do that rebuild-and-stage step automatically if it's
  ever forgotten. See `board/README.md` for the full workflow and
  `board/build.py --check` (also run in CI) to verify it isn't stale.
- **`BENCHMARKS.md`** — retrieval-quality, latency/cost, and isolation
  benchmark results produced by `benchmarks/` (see PH-6, EPIC-5) and the
  follow-on gap-analysis work (EPIC-6, `BENCH-*`). Regenerated by
  `make benchmark`; not produced by CI.
- **`INTEGRATION_TESTING.md`** — Docker/live-Db2 setup for the
  integration test suite.
- **`Chats.md`** — misc session notes.
- **`ai-agent-platform-competitive-analysis.md`** — market study of
  competing agent-memory platforms; the yardstick `audits/
  beta-readiness-audit-prompt.md` uses for feature-completeness checks.
- **`audits/`** — one-off, already-executed audit/remediation prompts,
  kept as historical records rather than active reference docs:
  - `audit-prompt.md`, `audit-prompt-2.md` … `audit-prompt-12.md` —
    post-step fix-pass prompts, each a record of a completed audit.
  - `beta-readiness-audit-prompt.md` — pre-worldwide-beta verification
    pass: re-audits every "Done" board story against current code and
    checks feature-completeness against the market study.

## A note on paths in older entries

Two reorgs have moved files since this project started, and neither
rewrote historical prose to match — both are recorded as dated entries in
`DECISIONS.md`, read those for the full rationale:

1. **2026-07-30** — everything in this folder moved from the repo root
   into `project-management/`. Entries in `DECISIONS.md` and the audit
   prompts that predate this move may reference these files by bare name
   (e.g. "read DECISIONS.md", "see BOARD.html") the way they were
   addressed when they lived at the repo root — read any such bare
   filename as `project-management/<file>` today.
2. **2026-07-31** — the 13 `audit-prompt*.md` / `beta-readiness-audit-
   prompt.md` files moved again, from `project-management/` directly
   into `project-management/audits/`. References between them (e.g.
   `beta-readiness-audit-prompt.md`'s mention of `audit-prompt-5.md`)
   still resolve as-is since both ends of every such reference moved
   together and remain siblings inside `audits/`. `DECISIONS.md`'s own
   historical entries that name these files by their pre-`audits/` path
   were left unedited, per the same "don't rewrite completed history"
   convention as the first move.

`PROMPTS.md` and `audits/beta-readiness-audit-prompt.md` are the two docs
still actively used going forward; both already state paths explicitly
rather than relying on this note.
